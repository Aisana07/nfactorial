# BudgetBuddy

Простое и интуитивно понятное веб-приложение для учета личных доходов и расходов. Помогает пользователям управлять бюджетом, отслеживать транзакции по категориям и анализировать свое финансовое состояние, в том числе с помощью AI-помощника.

## Демонстрация работы

https://nfactorial-xlvc.onrender.com


## Основные возможности

*   **Регистрация и Аутентификация:** Безопасный вход и регистрация пользователей с использованием JWT и хеширования паролей (bcrypt).
*   **Управление транзакциями:** Добавление, просмотр, редактирование и удаление доходов/расходов через модальное окно.
*   **Управление категориями:** Создание, просмотр, редактирование (название, цвет, иконка) и удаление категорий доходов и расходов.
*   **Информативный Дашборд:**
    *   Отображение текущего баланса, общих доходов и расходов за выбранный период (пока реализован выбор "по умолчанию").
    *   График движения средств (доходы/расходы по дням).
    *   Диаграмма структуры расходов по категориям.
    *   Список последних транзакций.
*   **AI-Аналитик (Бонусный уровень):**
    *   Интеграция с Google Gemini API для получения анализа финансового состояния и советов по оптимизации бюджета.
    *   Возможность задать вопрос AI-помощнику о своих финансах и получить ответ, основанный на данных пользователя.
*   **Frontend:** Чистый и адаптивный интерфейс, реализованный с использованием статических HTML, CSS, JavaScript и Bootstrap 5.
*   **Backend API:** RESTful API на Node.js/Express для взаимодействия с фронтендом.

## Технологический стек

*   **Backend:**
    *   Node.js
    *   Express.js
    *   MongoDB (база данных)
    *   Mongoose (ODM для MongoDB)
    *   JSON Web Tokens (jsonwebtoken) (для аутентификации)
    *   Bcrypt (для хеширования паролей)

    *   Helmet (для установки HTTP-заголовков безопасности, включая CSP)

*   **Frontend:**
    *   HTML5
    *   CSS3
    *   JavaScript (ES6+)
    *   Bootstrap 5 (CSS фреймворк)
    *   Chart.js (для построения графиков)
    *   Font Awesome (для иконок)
*   **Инструменты:**
    *   Git & GitHub (контроль версий)
    *   npm (менеджер пакетов)

## Установка и запуск

1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/Aisana07/nfactorial.git # Замените на URL вашего репозитория, если он другой
    ```
2.  **Перейдите в директорию проекта:**
    ```bash
    cd nfactorial # Или в папку вашего проекта
    ```
3.  **Установите зависимости:**
    ```bash
    npm install
    ```
4.  **Создайте файл `.env`** в корневой директории проекта и добавьте следующие переменные окружения:
    ```dotenv
    # Порт, на котором будет работать сервер (например, 3000)
    PORT=3000

    # Строка подключения к вашей базе данных MongoDB
    # Пример: mongodb://localhost:27017/budgetbuddy или строка из MongoDB Atlas
    MONGODB_URI=mongodb+srv://<username>:<password>@<cluster-url>/budgetbuddy?retryWrites=true&w=majority

    # Секретный ключ для подписи JWT токенов (придумайте сложную строку)
    JWT_SECRET=ваш_очень_секретный_ключ

    # API ключ для Google Gemini (получите в Google AI Studio)
    GEMINI_API_KEY=ваш_gemini_api_ключ

    # (Опционально, для CSP) URL вашего фронтенда, если он развернут отдельно
    # FRONTEND_URL=http://localhost:3000
    ```
    *Замените `<username>`, `<password>`, `<cluster-url>` и другие значения на ваши реальные данные.*
5.  **Запустите сервер в режиме разработки (с Nodemon):**
    ```bash
    npm run dev
    ```
    *Или запустите в "production" режиме (без автоматического перезапуска):*
    ```bash
    npm start
    ```
6.  **Откройте приложение в браузере:** Перейдите по адресу `http://localhost:PORT` (где `PORT` - значение из вашего `.env` файла, например `http://localhost:3000`).

## Процесс проектирования и разработки

1.  **Инициализация проекта:** Настройка `npm`, установка базовых зависимостей (`express`, `mongoose` и т.д.), создание структуры папок (`server`, `public`).
2.  **Backend API:** Разработка моделей данных (`User`, `Category`, `Transaction`) с использованием Mongoose. Реализация контроллеров и маршрутов для CRUD операций и аутентификации (регистрация, логин с JWT). Настройка middleware (`auth`, `helmet`, `morgan`).
3.  **Frontend (Итерация 1 - EJS):** Изначально фронтенд разрабатывался с использованием EJS как шаблонизатора Express. Были созданы базовые представления и макеты.
4.  **Frontend (Итерация 2 - Статический HTML + JS):** Принято решение перейти на статический фронтенд для лучшего разделения ответственности между клиентом и сервером. Шаблоны EJS были преобразованы в чистые HTML файлы. Логика отображения данных, взаимодействия с API и управления UI была перенесена в клиентские JavaScript файлы (`app.js`, `auth.js`, `dashboard.js`, `categories.js`). Для стилизации использовался Bootstrap 5, для графиков - Chart.js.
5.  **Интеграция AI:** Добавлен контроллер и маршрут для взаимодействия с Google Gemini API. Реализована логика получения финансового анализа и ответов на вопросы пользователя на основе его данных.
6.  **Отладка и Исправления:** В процессе разработки исправлялись различные ошибки: проблемы с Content Security Policy (CSP) для внешних ресурсов (CDN), ошибки на сервере (некорректный импорт моделей, ошибки в агрегациях MongoDB), проблемы с UI (отображение иконок, отсутствующие файлы).

## Уникальные подходы и методологии

*   **Переход от Server-Side Rendering (EJS) к Client-Side Rendering (Static HTML + JS):** Это ключевое архитектурное решение было принято для более четкого разделения Frontend и Backend. Frontend теперь полностью отвечает за отображение данных, получаемых от Backend API.
*   **Использование LLM (Google Gemini):** Интеграция большой языковой модели для реализации бонусной функциональности AI-аналитика, предоставляющего персонализированные финансовые советы.
*   **Разделение клиентского JS по страницам:** Создание отдельных JS файлов для каждой основной страницы (`dashboard.js`, `categories.js` и т.д.) для лучшей организации кода.

## Принятые компромиссы

*   **Статический HTML + JS вместо SPA:** Вместо полноценного Single Page Application (React, Vue, Angular) был выбран подход с отдельными статическими HTML-страницами, обслуживаемыми Express. Это упростило начальную настройку и развертывание, но привело к полной перезагрузке страницы при навигации между разделами.
*   **Неполная реализация функционала:** Для соблюдения сроков или фокусировки на ключевых аспектах, функционал на страницах "Транзакции" (кроме модального окна), "Аналитика" и "Настройки" не был полностью реализован и представлен в виде базовых HTML-заготовок.
*   **Базовая стилизация:** Использовался фреймворк Bootstrap 5 для ускорения разработки UI, что могло ограничить уникальность визуального дизайна.
*   **Фильтрация по дате:** Реализован только базовый UI для выбора диапазона дат на дашборде, но сама логика фильтрации данных по произвольному периоду еще не добавлена.

## Известные ошибки и проблемы

*   **Отсутствует файл аватара:** Файл `public/images/default-avatar.png` в репозитории является пустым placeholder'ом. Необходимо вручную заменить его на реальное изображение, чтобы аватар пользователя отображался корректно.
*   **Незавершенные страницы:** Страницы `/transactions`, `/analytics`, `/settings` содержат только базовую HTML-структуру и пустые JS-файлы. Основной функционал на них не реализован.
*   **Не работает фильтр по датам:** На главной странице (дашборде) добавлены поля для выбора произвольного диапазона дат, но логика применения этого фильтра (в JS и на бэкенде) отсутствует. Данные всегда загружаются за период по умолчанию.
*   **Потенциальная проблема с регистром имен файлов:** В процессе разработки наблюдалась ошибка линтера, связанная с регистром имен файлов моделей (`user.model.js` vs `User.model.js`). Хотя код работает, в некоторых средах (особенно на Windows/macOS с нечувствительной к регистру файловой системой) это может вызывать предупреждения или потенциальные проблемы при импорте. Рекомендуется придерживаться единого стиля именования (например, `PascalCase` для моделей: `User.model.js`).

## Выбор технологического стека

*   **Node.js / Express.js:** Выбраны как популярная, производительная и хорошо знакомая платформа для создания Backend API на JavaScript. Большое сообщество и экосистема npm упрощают разработку.
*   **MongoDB / Mongoose:** Гибкая NoSQL база данных, хорошо подходящая для проектов с возможно изменяющейся структурой данных. Mongoose предоставляет удобный интерфейс для работы с MongoDB из Node.js.
*   **Статический HTML, CSS, JavaScript:** Стандартные веб-технологии, обеспечивающие максимальную совместимость и гибкость для создания пользовательского интерфейса.
*   **Chart.js:** Легковесная и простая в использовании библиотека для создания интерактивных графиков и диаграмм.
*   **JWT** Стандартные и надежные решения для реализации безопасной аутентификации и хранения паролей.
*   **Google Gemini:** Выбран как мощный и доступный LLM для реализации бонусной AI-функциональности.
